# ray-hive 1.1

`ray-hive` 1.1 is an Alpha release of the independent HiveServer2 datasource for Ray Data. It
publishes the query-only contract and current-Ray compatibility work completed after 1.0.

## Highlights

- Raw SQL now accepts one conservatively validated top-level `SELECT`. DDL, DML, multiple
  statements, comments, Hive variable substitution, and ambiguous quoting or parentheses fail
  before credential resolution or network access.
- `unsafe_where_sql` is confined to one balanced predicate fragment. Structured filters accept
  only the built-in immutable predicate tree with exact `Column` leaves.
- The built-in `ray_hive.sql` predicate builder is a stable public API. The lower-level
  `HiveServer2Datasource` remains a DeveloperAPI, and only `read_hive()` guarantees
  `max_retries=0` for strict no-replay reads.
- The Ray Data compatibility window expands through final Ray 2.58 releases. The multi-node
  runtime uses Ray 2.58.0 with measured Thrift 0.22.0 identity.
- Release candidates use commit-bound CI, Hive, and Ray cluster evidence; release jobs consume
  those artifacts without rerunning the same long suites.

## Compatibility

- Python 3.12 and 3.13.
- Final Ray releases `>=2.55.1,<2.59`.
- PyArrow 19.0.1 and Thrift 0.22.0 exactly.
- Apache Hive 4.2.0 is the required real-infrastructure profile.
- Native binary transport with `NOSASL` is the implemented runtime profile.

Pre-release, development, post-release, and Ray 2.59 or later versions fail closed. Hive 4.0.1
and 3.1.3 remain compatibility targets rather than supported profiles.

## Upgrade notes

- Applications that used raw SQL for DDL, DML, `SET`, `WITH`, `EXPLAIN`, comments, or multiple
  statements must move those operations outside `ray-hive`. They were never part of the documented
  read-only contract.
- Applications should continue to use top-level `read_hive()`. Direct Datasource use does not
  inherit the strict retry guarantee.
- Custom `Column` or `Predicate` subclasses are not supported SQL extension points.

## Known limitations

- Source parallelism is one sequential HiveServer2 operation in strict mode. Multiple Arrow blocks
  and downstream Ray parallelism do not imply file-level or split-level source parallelism.
- `independent_queries` remains experimental and uses independent Hive snapshots.
- HTTP, SASL, Kerberos, LDAP, CUSTOM authentication, PyHive, Impyla, and JDBC remain unsupported.
- Production Core status is not claimed; the broader security, network-purity, fault, Hive-version,
  table-format, performance, and multi-maintainer evidence remains incomplete.

The repository `SUPPORT.md`, compatibility documentation, and exact-SHA evidence manifests define
the complete support and validation boundary for this release.
