# ray-hive 1.0

`ray-hive` 1.0 is an Alpha release of an independent, community-maintained Ray Data datasource
that reads query results through Apache HiveServer2.

## Highlights

- HiveServer2 is the only client-side data path; Ray drivers and workers do not read Hive
  Metastore, HDFS, object storage, table locations, manifests, or data files.
- Native TCLIService transport and V6 columnar result decoding are included.
- Strict reads submit one Hive query, stream multiple Arrow blocks, and force Ray task
  `max_retries=0` to avoid replay after partial output.
- Credential references, safe predicates, deterministic cleanup, and fail-closed unsupported
  capability handling are included.

## Compatibility

- Python 3.12 and 3.13.
- Ray 2.55.1 and PyArrow 19.0.1.
- Apache Hive 4.2.0 is the primary conformance target.

## Known limitations

- The initial Core profile supports native binary transport with NOSASL only; other transports,
  authentication mechanisms, and drivers remain unsupported until their real matrices pass.
- This release does not claim HDFS-level, file-level, or multi-query source parallelism.
- `independent_queries` is experimental and does not provide a single snapshot across queries.
- Production Core status is not claimed until the real Hive, security, network-purity, cancellation,
  and Ray execution evidence is complete.

The complete compatibility matrix and validation evidence are maintained in the repository
documentation and release workflow.
